# Проект для портфолио

«Мой план лучше» — AI-агент, с которым можно спорить о плане проекта.
Он объясняет приоритеты и компромиссы, хранит возражения и предлагает изменения,
а пользователь сравнивает варианты и принимает решение. Сервер проверяет время,
зависимости и защищённые задачи, прежде чем разрешить принять план.

## Что показать

Используйте [сценарий демонстрации](demo.md): цель → план → возражение → потеря времени →
сравнение → принятие → выполнение → память. Для свободного диалога нужен локальный запуск
с YandexGPT. Режим `?demo=1` показывает подготовленный сценарий без ключа и расходов.

В описании работы полезно выделить три решения: разделение подтверждённых фактов
и сводки диалога, проверку структурированного ответа модели кодом и сохранение
изменений с контролем revision. Схема и причины решений — в [архитектуре](architecture.md).

## Размещение

Репозиторий и запись демонстрации можно добавить в портфолио. Ссылка Sites в README
сейчас ведёт на приватное демо: перед отправкой другим людям нужно отдельно настроить
его аудиторию. В демо нет серверных ключей или пользовательской базы.

Для настоящего агента: PostgreSQL, резервные копии, сильный APP_PASSWORD и HTTPS-прокси.
Приложение рассчитано на одного владельца; пароль нельзя раздавать посетителям портфолио,
поскольку он разрешает редактировать и удалять проекты и расходовать квоту модели.
Для посетителей используйте отдельное статическое демо.

Пример запуска за локальным HTTPS-прокси:

```bash
uvicorn src.server:app --host 127.0.0.1 --port 8000 --workers 2 --proxy-headers --forwarded-allow-ips 127.0.0.1
```

Настройте APP_ALLOW_HTTP=false, передачу фактического адреса клиента и HTTPS-схемы
от доверенного прокси, а также общий лимит попыток входа на прокси при нескольких процессах.
Docker Compose предназначен для локального запуска и публикует порт на 127.0.0.1.
Не меняйте это на публичный HTTP без отдельной настройки HTTPS и доступа.

## Проверка перед показом

- Миграции применяются при запуске; перед обновлением существующей базы сохраните копию.
- Проверки из README должны пройти на SQLite и PostgreSQL без внешних HTTP-запросов.
- Пройдите основной сценарий, затем перезагрузите страницу и проверьте сохранность проекта.
- Уберите реальные данные и секреты из записи экрана; используйте отдельный показательный проект.

Оценки длительности остаются предположениями модели. Проверка ссылок на требования
не доказывает смысловую полноту плана. Раздельные аккаунты и командная работа в эту
версию не входят. Предел токенов ограничивает один запрос, а не месячные расходы
провайдера; для них нужны отдельные ограничения платёжного аккаунта.
