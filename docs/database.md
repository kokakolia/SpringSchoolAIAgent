# База данных и миграции

Поддерживаются PostgreSQL (asyncpg) и SQLite (aiosqlite). URL берётся из `.env` или
переменной `DATABASE_URL`. Скрипт `run-local.ps1` по умолчанию выбирает локальную SQLite;
флаг `-UsePostgres` сохраняет URL из настроек. Эти базы независимы: переключение не
переносит проекты между ними.

## Миграции

```bash
python -m alembic upgrade head
python -m alembic current
python -m alembic check
```

Сервер и прежний CLI также выполняют `upgrade head` через `init_db()`. В PostgreSQL
запуски нескольких экземпляров приложения защищены транзакционной блокировкой.
После обновления приложение сравнивает схему с моделями и останавливает запуск,
если обнаруживает несовместимость, вместо молчаливого изменения данных.

- `0001_initial`: фиксированные определения таблиц; отсутствующие таблицы и индексы
  создаются, существующие сохраняются. Подходит для перехода с прежнего `create_all`.
- `0002_utc_timestamps`: ранние поля времени проекта переводятся из timestamp без
  часового пояса в timestamptz. Старые значения интерпретируются как UTC, как они
  записывались ранней версией. SQLite хранит UTC без отдельной метки часового пояса.

Перед обновлением существующей рабочей базы сделайте резервную копию:

```bash
pg_dump -h 127.0.0.1 -U postgres -d taskmaster -Fc -f taskmaster-backup.dump
```

Для SQLite закройте приложение и скопируйте `.local/deadline.db`. Файлы баз и резервных
копий исключены из Git. Откат до `base` удаляет таблицы; используйте его только на
одноразовой тестовой базе. Восстановление рабочей базы выполняйте из резервной копии.

Новая миграция:

```bash
python -m alembic revision --autogenerate -m "describe schema change"
python -m alembic upgrade head
python -m alembic check
```

Проверьте сгенерированный файл перед применением. Определения в существующих миграциях
не зависят от текущих ORM-моделей.

## Проверка PostgreSQL

Задайте `TEST_DATABASE_URL` в окружении процесса и выполните `python -m pytest -q`.
Тестовый пользователь должен иметь право создавать схемы в выбранной тестовой базе.
Фикстура создаёт уникальную схему `test_<uuid>`, задаёт её search_path и удаляет только
эту схему после теста. Внешние HTTP-запросы во всём наборе тестов заблокированы.

Проверяются обычные сценарии приложения, повтор миграций, принятие старой схемы,
сохранность данных и перевод временных меток UTC. В CI используется PostgreSQL 16;
локальная проверка также выполнена на PostgreSQL 18.6.

## Docker

Данные сохраняются в томе `postgres_data`. База доступна приложению внутри сети Compose.
`docker compose down` сохраняет том; флаг `-v` удаляет данные тома.
