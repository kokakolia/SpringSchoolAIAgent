# Память проекта и управление контекстом

Постоянная память для «До дедлайна». Прежний интерфейс и API матрицы удалены; исторические данные можно выгрузить через CLI (legacy.md). Сохраняемый диалог дополнен структурированными планами, их принятием и интерфейсом: см. `planning-api.md`.

## Запуск

Установите `requirements.txt`, настройте `.env` и запустите `python main.py serve`. Схема обновляется версионированными миграциями Alembic при `init_db()`. Существующие задачи и проекты сохраняются; подробности и резервное копирование описаны в `database.md`.

Для локального эксперимента можно использовать `DATABASE_URL=sqlite+aiosqlite:///./local.db`. Сервис рассчитан на одного пользователя. Разделение по `project_id` предотвращает случайное смешение контекста; авторизацию и проверку владельца необходимо добавить до многопользовательского размещения.

## Создание и диалог

`POST /api/projects`

```json
{
  "title": "Защита проекта",
  "state": {
    "goal": "Показать рабочий сценарий на защите",
    "success_criteria": ["Создание и сохранение задачи работают"],
    "constraints": ["Анимации обязательны"],
    "available_minutes": 360,
    "deadline": "2026-11-01T18:00:00+03:00",
    "timezone": "Europe/Istanbul"
  }
}
```

Ответ содержит `id` и `revision`. `GET /api/projects` возвращает проекты; `GET /api/projects/{id}` — текущее состояние.

`POST /api/projects/{id}/messages`

```json
{
  "request_id": "97b8ff80-62c0-455e-80ed-b70e428864ad",
  "base_revision": 0,
  "text": "Анимации важны для показа. Что можно сократить вместо них?"
}
```

Сохраняются исходное сообщение, завершённый ответ модели и полученная статистика usage. Ошибка модели не создаёт частичный ход. Повтор успешного запроса с тем же UUID и текстом возвращает сохранённый ответ. Для нового сообщения нужен новый UUID и актуальная ревизия.

`GET /api/projects/{id}/messages` возвращает полный журнал независимо от сжатия. Ручное изменение подтверждённого состояния: `PATCH /api/projects/{id}` с полями `base_revision` и `state` (полное новое состояние). Ответ модели сам по себе не перезаписывает подтверждённые требования.

## Подсчёт

- `GET /api/projects/{id}/context` — текущие входные сообщения и локальная оценка размера.
- `GET /api/projects/{id}/context?exact=true` — подсчёт через токенизатор Yandex, требует ключей и сети.
- `input_tokens` всегда сопровождается `count_method`: `estimated_utf8` или `yandex_tokenizer`.
- Локальная эвристика — число байт JSON в UTF-8, делённое на три. Она не гарантирует точный размер или верхнюю границу.
- Настраиваемый бюджет `CONTEXT_BUDGET_TOKENS` включает резерв `RESPONSE_RESERVE_TOKENS`. Это ограничение приложения; его нужно согласовать с реальным окном выбранной модели. Перед каждым запросом агента проекта выполняется точный подсчёт полного ввода. Порог сжатия задаётся `CONTEXT_COMPRESSION_THRESHOLD` (по умолчанию 0.75). Если ввод с резервом достигает порога, накопленный диалог автоматически сжимается; если запрос всё равно превышает бюджет, возвращается HTTP 413 без генерации ответа.

Точный подсчёт использует [Yandex TokenizeCompletion](https://aistudio.yandex.ru/en/docs/ai-studio/text-generation/api-ref/Tokenizer/tokenizeCompletion). Текущая ветка диалога не передаёт инструменты в этот вызов. Если инструменты будут добавлены, их вклад нужно будет учитывать отдельно: документация указывает, что поле tools токенизатором игнорируется.

## Сжатие и восстановление

Отправьте `/compress` через endpoint сообщений либо вызовите `POST /api/projects/{id}/context/compress`:

```json
{
  "request_id": "7c8ff1ae-7323-4ad2-96d9-c32dafaa5c66",
  "base_revision": 1
}
```

Модель получает команду сжать текущую память, сохранив ограничения, решения, возражения, вопросы и предположения раздельно. Результат проверяется Pydantic-схемой. Сжатая версия должна быть меньше исходной по явно обозначенной локальной оценке. После проверки одна транзакция сохраняет `before_compression`, `compressed` и переключает указатель текущей версии.

Ошибка, некорректный/оборванный ответ, отсутствие уменьшения или изменение проекта во время запроса оставляют текущую версию целой. Полный журнал не удаляется. При повторном сжатии учитываются предыдущая сводка и новые сообщения. Подтверждённые факты проекта всегда заново добавляются в системное сообщение.

- `GET /api/projects/{id}/context/versions` — история версий.
- `GET /api/projects/{id}/context/versions/{version_id}` — снимок входных сообщений и сводка.
- `POST /api/projects/{id}/context/versions/{version_id}/restore` — восстановление с новым `request_id` и актуальной `base_revision`.

Восстановление создаёт ещё одну версию. Оно возвращает старый способ сборки контекста и добавляет сообщения, появившиеся позже. Текущие факты проекта остаются актуальными; восстановление контекста не откатывает работу пользователя.

HTTP 409 означает конфликт ревизии или повторное использование UUID с другим содержимым. Клиент должен перечитать состояние и предложить повторное действие. HTTP 503 означает недоступность или некорректный ответ модели; HTTP 422 — некорректный запрос либо неэффективное сжатие.

Автоматическое сжатие готовится перед ответом и сохраняется вместе с ним одной транзакцией: версии до/после, новые сообщения, указатель текущего контекста и одно увеличение revision. Ошибка ответа или конфликт не оставляют частично сохранённого сжатия. Сводка проверяется на уменьшение точного размера полного запроса; свежий ввод пользователя, системная инструкция, факты и данные планирования сохраняются полностью. Повторные попытки исправления плана тоже проходят точный подсчёт.

В usage ответа сохраняются `context_checks`: точные показатели до/после и признак сжатия. Интерфейс памяти по умолчанию показывает локальную оценку базового диалога; полный запрос планирования может быть больше. После сжатия порог может оставаться превышенным из-за фиксированных данных, но жёсткий бюджет не превышается. Без новых сообщений уже сжатая память повторно не сжимается. Если полная история не помещается в запрос сжатия, она обрабатывается последовательными частями с переносом предыдущей сводки. Слишком длинное отдельное сообщение делится без удаления исходного текста. Перед каждой частью выполняется точный подсчёт. `MAX_COMPRESSION_PARTS` ограничивает число вызовов сжатия (по умолчанию 32); ошибка части сохраняет исходный контекст целиком.

Команда `/compress` и окно памяти с просмотром и восстановлением версий остаются доступны.

## Управление проектами

`PATCH /api/projects/{id}` принимает `base_revision` и новое `title` и/или полное `state`. Можно переименовать проект, не передавая остальные условия. Пустое название и пустой набор изменений отклоняются. Название сохраняется в событии `project_renamed`; переписка, планы, память и прогресс остаются на месте. Переименование не делает актуальное предложение плана устаревшим. Изменение условий по-прежнему требует проверки плана.

`DELETE /api/projects/{id}` с JSON `{ "base_revision": 4 }` удаляет проект, его сообщения, версии контекста и планов, прогресс и события одной транзакцией. Перед удалением проверяется revision. Конфликт возвращает 409, отсутствующий проект — 404. Данные других проектов и прежняя таблица матрицы не затрагиваются. Поздний ответ модели не может восстановить удалённый проект.

В интерфейсе действия находятся в меню «⋯» рядом с проектом и его заголовком. Удаление требует подтверждения с названием. После удаления текущего проекта открывается другой; после удаления последнего показывается пустой экран. Черновик нового проекта сохраняется независимо.


## Одновременные обращения к модели

Диалог, предложение плана и ручное сжатие сначала занимают одну операцию проекта
в `project_model_operations`. Повторный или иной параллельный запрос получает `409`
до токенизации и генерации. После успешного завершения повтор с тем же request_id
возвращает сохранённый результат без новой генерации.

Операция ограничена 180 секундами (`MODEL_OPERATION_TIMEOUT_SECONDS`, допустимо 1–180).
При ошибке, отмене или тайм-ауте блокировка освобождается. После аварийного завершения
процесса она истекает через лимит операции плюс 60 секунд. Старый владелец не может
освободить блокировку нового процесса. Разные проекты работают независимо.

Правки пользователя разрешены во время генерации; revision по-прежнему защищает запись
результата. Удаление проекта удаляет блокировку, а запоздалый ответ не сохраняется.
Отмена локального HTTP-запроса не гарантирует отмену уже принятой провайдером генерации:
это не гарантия однократного списания при сетевом обрыве или аварии провайдера.
